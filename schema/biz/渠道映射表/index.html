    cloud_cube_trade.channel_mapping#

    ads_dbs_trade_shop_pay_channel_di 的补充维度表。用来查"某渠道里多少是现金付的、多少是微信付的、多少是抖音次卡"这类支付方式拆解问题。

    库 cloud_cube_trade，业务库非数仓层。

    ⚠️ 这张表的定位（划重点）#

    容易踩的坑

    这张表的 payment_channel 存的是支付方式（现金/扫码/微信/支付宝/优惠券/储值/次卡/代金券/团购券），不是渠道名。

    • source_channel = 渠道名（美团外卖、抖音团购、pos收银、微信小程序）
    • payment_channel = 支付方式（现金、扫码支付、微信、支付宝、优惠券、储值、抖音次卡…）
    • 和 shop_di / food_di 没有字段名上的对应关系，不要用它来做跨表渠道关联
    • 不是跨表关联的枢纽，只是 pay_channel_di 的补充维度

    字段定义#

    字段 类型 注释
    id int(11) 自增主键
    channel_type varchar(200) 渠道大类：团购 / 外卖 / 自营（仅 3 种）
    channel_type_code varchar(200) 渠道类型编码
    source_channel varchar(200) 渠道名（快手团购、美团外卖、pos收银…）
    source_channel_code varchar(200) 渠道名编码
    payment_channel varchar(200) 支付方式（现金/扫码/微信/支付宝/优惠券/储值/次卡/代金券/团购券…）
    payment_channel_code varchar(200) 支付方式编码
    fulfillment_method varchar(200) 履约方式（当前全为空）
    fulfillment_method_code varchar(200) 履约方式编码
    writeoff_channel varchar(200) 核销渠道（当前全为空）
    writeoff_channel_code varchar(200) 核销渠道编码
    payment_channel_source varchar(255) 支付名（未用到）

    source → payment 拆解示例#

    快手团购（channel_type = 团购），6 种支付方式：

    source_channel payment_channel
    快手团购 快手代金券、优惠券、现金、扫码支付、快手次卡、快手团购券

    pos收银（channel_type = 自营），4 种支付方式：

    source_channel payment_channel
    pos收银 储值、扫码支付、现金、优惠券

    微信小程序（channel_type = 自营），5 种支付方式：

    source_channel payment_channel
    微信小程序 微信、储值、优惠券、积分支付、其他

    美团/大众点评团购（channel_type = 团购），8 种支付方式：

    source_channel payment_channel
    美团/大众点评团购 点评代金券、现金、扫码支付、美团在线点、优惠券、点评次卡、点评团购券

    使用场景#

    channel_mapping 的唯一正确用法——查支付方式分布：

    -- 查 2026-10 抖音团购里各种支付方式的流水
SELECT 
    cm.payment_channel AS 支付方式,
    SUM(pc.amount) AS 流水
FROM tll_bi_dw.ads_dbs_trade_shop_pay_channel_di pc
JOIN cloud_cube_trade.channel_mapping cm 
    ON pc.payment_channels = cm.source_channel
WHERE pc.pt LIKE '2026-10%'
  AND cm.source_channel = '抖音团购'
GROUP BY cm.payment_channel;

    不要用它做的事#

    ❌ 错误用法 为什么错
    JOIN shop_di 做跨表渠道关联 payment_channel 是支付方式，不是渠道名
    查 source_channel 和 pay_channel_di.payment_channels 的映射 两者字段值不同（mapping 里没有甜啦啦小程序等）
    当核销/履约配置表 fulfillment_method 和 writeoff_channel 当前全是空

    注意事项#

    注意
    1. 跨库：数仓表在 tll_bi_dw，这张表在 cloud_cube_trade，示例 SQL 的库名前缀不要漏。
    2. 当前 fulfillment_method 和 writeoff_channel 全为空，不要依赖这两个字段。
    3. 渠道新增后，需要同步补 channel_mapping 里的 source_channel → payment_channel 拆解。
