# 来源渠道 vs 支付渠道 对比

对比 `ads_dbs_trade_shop_di`（来源渠道）与 `ads_dbs_trade_shop_pay_channel_di`（支付渠道）。

## 核心结论

{{< notice warning "两表 ETL 链路不同，渠道名不可比" >}}
- `shop_di`（来源渠道）：按**订单来源**归并
- `shop_pay_channel_di`（支付渠道）：原始支付明细经 `cloud_cube_trade.channel_mapping` 归并后聚合

**两张表的 `channel_name` / `payment_channels` 字段天然对不上，不要逐渠道 JOIN 或对比。** 只能对比**总额**。
{{< /notice >}}

## 为什么渠道名不同

根本原因：**历史上用美团 POS 收银，现在逐步切自研收银。美团 POS 的接口数据粒度不够，区分不了同一支付渠道来自哪个入口（POS / 自营外卖 / 小程序），ETL 只能做模糊归并。**

| 来源 | shop_di | shop_pay_channel_di |
|---|---|---|
| 归并依据 | 美团 POS 系统的渠道口径（受数据粒度限制） | 自研收银 + `channel_mapping` 配置（精细） |
| 自营外卖 | 美团 POS 数据分不清来源，ETL 模糊归并出一条"自营外卖" | 京东外卖含自营 + 在线点，没有单独的"自营外卖" |
| 小程序 | 三条并存（小程序 / 微信 / 支付宝） | 拆成 7 条（含甜啦啦系） |
| 线上新增团购 | 合并进主团购渠道 | 单独列出 |
| pos收银 | 含团购核销部分 | 仅 POS 直接收款 |

{{< notice warning "自营外卖口径" >}}
shop_di 的 `自营外卖` 是**美团 POS 数据粒度不够的产物**——同一个支付渠道（如抖音团购券）可能来自 POS / 自营外卖 / 小程序多个入口，但美团接口返回的原始数据分不清来源。

京东外卖占自营外卖的绝大多数，所以实践里**自营外卖 ≈ 京东外卖**：
- `shop_di.京东外卖` ≈ 自研 POS 的京东外卖
- `shop_di.自营外卖` ≈ 美团 POS 的京东外卖（混淆项）
- 两表总额对得上，就是这部分拆分方式不同

后续全切自研 POS 后，自营外卖这个模糊项会消失。
{{< /notice >}}

## 正确姿势

{{< notice info "建议" >}}
- 要**来源渠道口径** → 用 `shop_di`
- 要**支付渠道口径** → 用 `shop_pay_channel_di`（中台驾驶舱以此为基准）
- 要跨表按渠道对比 → **不要做**，两套 ETL 结果不可直接对齐
{{< /notice >}}
