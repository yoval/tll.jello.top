# 月末运营状态

查指定月份**该月最后一个有数据的日子**的门店运营状态汇总。数据来自门店信息 SCD 表 `shop_info`，每个门店在每个时点恰好命中一行版本记录。

- **数据表**：`Tianlala.shop_info`（MySQL 8.4）
- **粒度**：统计日期 × 省 × 市 × 门店类型 × 运营状态
- **口径**：统计日期 = 该月内实际最新的 `end_date`（月末还没数据时自动回退，如 10 月落到 10/30）；只计入该日仍有效的门店版本行，即 `start_date <= 统计日期 AND end_date >= 统计日期`
- **过滤**：与 `shop_current` 的清洗口径一致——只保留 `TLL` / `ZYD` 前缀门店，剔除门店名称含「测试 / 茶语 / 茶讯 / 柬埔寨」的无效门店（原因见下方注意事项）
- **门店类型**：按 `门店编号` 前缀判定，`TLL*` = 加盟店，`ZYD*` = 直营店（不用 `门店类型` 字段，原因见下方注意事项）
- **输出列**：统计日期、省、市、门店类型、运营状态、门店数

{{< notice info "版本行是闭区间" >}}
`start_date / end_date` 是**闭区间** `[start_date, end_date]`，行与行之间无缝衔接（如 `01-01~01-02` 之后直接是 `01-03~01-03`）。所以任何一个日期时点，每个门店**恰好命中一行**，不会重复也不会漏。实测 2025-01-31 命中 6,605 行 / 6,605 家门店，一一对应（叠加下方脏门店过滤后为 6,603 家）。
{{< /notice >}}

## SQL

只改 `@month` 一个变量。第一步先取该月**实际最新数据日期**（`MAX(end_date)`），第二步按这个日期取在册门店，所以月末没数据时会自动用月末前最后一个有数据的日子。

```sql
SET @month = '2026-09';   -- 只改这里

WITH stat AS (
    SELECT MAX(end_date) AS stat_date          -- 该月实际最新数据日期
    FROM Tianlala.shop_info
    WHERE end_date >= CAST(CONCAT(@month, '-01') AS DATE)
      AND end_date <= LAST_DAY(CONCAT(@month, '-01'))
)
SELECT
    DATE_FORMAT(st.stat_date, '%Y/%c/%e') AS 统计日期,
    IFNULL(s.省, '未知')                  AS 省,
    IFNULL(s.市, '未知')                  AS 市,
    CASE WHEN s.门店编号 LIKE 'TLL%' THEN '加盟店'
         WHEN s.门店编号 LIKE 'ZYD%' THEN '直营店'
         ELSE '未知' END                  AS 门店类型,
    s.运营状态,
    COUNT(*)                             AS 门店数
FROM stat st
JOIN Tianlala.shop_info s
  ON s.start_date <= st.stat_date
 AND s.end_date   >= st.stat_date          -- 只保留该日仍有效的门店
WHERE s.门店编号 REGEXP '^(TLL|ZYD)'        -- 只保留白名单前缀
  AND IFNULL(s.门店名称, '') NOT REGEXP '测试|茶语|茶讯|柬埔寨'   -- 剔除无效门店
GROUP BY st.stat_date, s.省, s.市,
         CASE WHEN s.门店编号 LIKE 'TLL%' THEN '加盟店'
              WHEN s.门店编号 LIKE 'ZYD%' THEN '直营店'
              ELSE '未知' END,
         s.运营状态
ORDER BY st.stat_date, s.省, s.市, 门店类型, 门店数 DESC;
```

{{< notice warning "GROUP BY 不能只写别名" >}}
`GROUP BY` 里写别名 `门店类型` 在部分环境（`sql_mode=ONLY_FULL_GROUP_BY` 的 MySQL 5.7 / 8.0）会报 `1055 Expression #4 of SELECT list is not in GROUP BY clause ... contains nonaggregated column 's.门店编号'`——因为它把别名展开成 `CASE` 表达式后，发现里面的 `s.门店编号` 不在 GROUP BY 中。所以 `GROUP BY` 要重复完整的 `CASE` 表达式（`SELECT` 和 `ORDER BY` 仍可用别名）。
{{< /notice >}}

{{< notice warning "LAST_DAY 不能直接吃月份" >}}
`LAST_DAY('2026-09')` **返回 NULL**，月份格式不是合法日期。必须拼成完整日期再取月末：`LAST_DAY(CONCAT(@month, '-01'))`。实测 `LAST_DAY('2026-02')` 也是 NULL，而 `LAST_DAY(CONCAT('2026-02','-01'))` 正确返回 `2026-02-28`。
{{< /notice >}}

{{< notice info "为什么不用月末直接筛" >}}
`shop_info` 的 `end_date` 最晚只到当前有数据的日期。查当月（如 `@month = '2026-10'`，而 10/31 还没到）时，`end_date >= 月末` 会命中 0 行。先取 `MAX(end_date)` 再筛，能同时兼容历史月份（自然等于月末）和当月（自动回退到最新一天）。
{{< /notice >}}

{{< notice warning "必须过滤脏门店，否则数字偏大" >}}
`shop_info` 里混有 3 家无效门店，直接汇总会算进去：

| 门店编号 | 门店名称 | 命中关键词 | 在册区间 |
|---|---|---|---|
| `TLL05278` | 蚌埠茶语信息咨询有限公司 | 茶语 | 2025-01-01 ~ 2026-10-17 |
| `TLL07419` | 蚌埠茶讯信息咨询有限公司 | 茶讯 | 2025-01-01 ~ 2025-12-30 |
| `TLL90012` | 信息部（测试11） | 测试 | 2025-06-12 单日 |

这条过滤条件照搬自门店信息同步脚本 [store_info_format](file:///C:/Users/Administrator/OneDrive/Script/Daily/store_info_format) 的 `store_data_cleaner`，也就是生成 `shop_current` 时用的清洗口径：

- `_handle_missing_data`：删除 `门店编号` 为空的行，`门店名称` 去首尾空格
- `_filter_invalid_records`：`门店名称` 不含 `测试 | 茶语 | 茶讯 | 柬埔寨`，且 `门店编号` 以 `TLL` / `ZYD` 开头（不匹配即剔除）
- `_process_special_stores`：`ZYD` 前缀的门店管理人员统一记为「直营店」

SQL 里等价写成 `门店编号 REGEXP '^(TLL|ZYD)'` + `门店名称 NOT REGEXP '测试|茶语|茶讯|柬埔寨'`。`门店名称` 用 `IFNULL(..., '')` 包一层，与脚本 `str.contains(..., na=False)` 的行为对齐——名称为空时判为「不含关键词」保留，而不是判为 NULL 被剔除。

实测影响：2025 年 1~11 月每月多算 2 家（茶语 + 茶讯），2025-12 ~ 2026-09 每月多算 1 家（茶语），2026-10 已无影响（茶语 10/17 终止）。
{{< /notice >}}

## 参数调整

- **只看加盟店 / 直营店**：在 `WHERE` 里加 `AND s.门店编号 LIKE 'TLL%'`（或 `'ZYD%'`）
- **只查营业中**：加 `AND s.运营状态 = '营业中'`
- **只查某省**：加 `AND s.省 = '安徽省'`（注意用全称，如 `广西壮族自治区`）
- **只查某市**：加 `AND s.市 = '合肥市'`
- **按门店类型汇总（不分省市）**：`GROUP BY st.stat_date, 门店类型`，去掉 `s.省`、`s.市` 列
- **省市汇总（不分类型和状态）**：`GROUP BY st.stat_date, s.省, s.市`，去掉 `门店类型`、`s.运营状态` 列 → 约 367 行
- **省级汇总**：`GROUP BY st.stat_date, s.省` → 31 行
- **改成按门店数全局排序**：`ORDER BY` 只留 `门店数 DESC`

## 注意事项

{{< notice warning "直辖市的「市」字段存的是区县名" >}}
北京、上海、天津、重庆四个直辖市，`省` 是直辖市名，但 `市` 字段填的是**区/县级名称**，不是地级市。实测 2026 年 9 月：上海市 8 个“市”值全是区名（奉贤区、宝山区、浦东新区…），北京市 12 个、天津市 14 个、重庆市 19 个（含自治县）同样如此。

其余 27 个省/自治区才是正常的地级市（如 `安徽省` + `合肥市`）。所以直辖市下钻到“市”这一层时，实际粒度是区级，和普通省的市级不可直接横向对比。
{{< /notice >}}

{{< notice warning "门店类型用编号前缀判定，不用门店类型字段" >}}
`门店编号` 全表只有 `TLL` / `ZYD` 两种前缀，无第三种。而 `门店类型` 字段存在两类问题：

1. **空值行**：同一家门店 `ZYD00118`（安徽蚌埠）在不同版本行里分别记 `NULL` 3 行、字符串 `'nan'` 1 行，按前缀判定本应是直营店
2. **矛盾行**：`TLL05278`（蚌埠茶语信息咨询有限公司）编号是 `TLL` 前缀，字段却记 `直营店`——该门店已被上方关键词「茶语」过滤剔除

所以按前缀判定更干净。实测 2026-09-30 叠加脏门店过滤后：按前缀是加盟 7,266 / 直营 80；用字段则 `ZYD00118` 那行会落进 `ELSE '未知'`，多出一个「未知」组。`ELSE '未知'` 只为兜底未来可能出现的其他前缀。
{{< /notice >}}

{{< notice warning "月中终止的门店不在统计日" >}}
门店若在统计日前终止且无后续版本行（例如 9 月 29 日解约、之后没有再建版本），该日 `end_date >= 统计日期` 条件会把它排除。实测 2026 年 9 月这类门店有 65 家。这是“截至统计日仍在册”口径的正常表现——要查含已解约门店的全历史请用 [全量门店查询]({{< ref "/queries/shop/全量门店查询" >}})。
{{< /notice >}}
