# 产品月销售查询

按**商品名称**汇总指定月份的流水、实收、订单量、销量。数据来自产品销售日表，原表粒度是 门店 × 日期 × 渠道 × 商品，这里把门店、渠道、日期全部折叠，只留商品维度。

- **数据表**：`tll_bi_dw.ads_dbs_trade_food_di`（[产品销售（来源渠道）]({{< ref "/schema/ads/ads_dbs_trade_food_di" >}})）
- **粒度**：月份 × 商品名称
- **输出列**：月份、商品名称、流水、实收、订单量、销量

## SQL

```sql
SELECT
    SUBSTR(CAST(business_date AS VARCHAR(8)), 1, 6) AS 月份,
    item_name                                       AS 商品名称,
    SUM(dp_total_amount)                            AS 流水,
    SUM(dp_pay_amount)                              AS 实收,
    SUM(dp_order_count)                             AS 订单量,
    SUM(dp_item_count)                              AS 销量
FROM tll_bi_dw.ads_dbs_trade_food_di
WHERE business_date >= 20261001 AND business_date <= 20261031
GROUP BY SUBSTR(CAST(business_date AS VARCHAR(8)), 1, 6), item_name
ORDER BY 流水 DESC;
```

月份列由数据自身推出（`20261001` 取前 6 位得 `202610`），不是手写常量。换月份只改 `WHERE` 里的两个日期；把区间放宽到跨月（如 `20260901 ~ 20261031`），查询会自动按月份分行输出。

## 参数调整

- **按商品类型过滤**：加 `AND item_type = '单品'`（可选值：`单品` / `套餐` / `小料` / `周边` / `其它`）
- **只看某省**：加 `AND prov_name = '安徽省'`
- **只看某市**：加 `AND city_name = '合肥市'`
- **只看某渠道**：加 `AND channel_name = '美团外卖'`
- **排除赠茶（实收为 0）**：加 `HAVING SUM(dp_pay_amount) > 0`
- **按销量排序**：`ORDER BY 销量 DESC`

## 注意事项

{{< notice warning "business_date 不能直接 LIKE '202610%'" >}}
`business_date` 是 **bigint**（值为 `20261001` 这种），不是字符串。想用 `LIKE '202610%'` 必须先转成字符：

```sql
WHERE CAST(business_date AS VARCHAR(8)) LIKE '202610%'
```

但依赖隐式转换或 `CAST` 在不同 Doris 版本上行为不保证，**直接用数值区间最稳**（`>= 20261001 AND <= 20261031`），也是上面主查询的写法。
{{< /notice >}}

{{< notice warning "订单量不是门店订单数" >}}
`dp_order_count` 是**商品订单量**——同一订单里买了 3 种商品，会被 3 个商品各记 1 次。所以 `SUM(dp_order_count)` 只能理解为「该商品出现在多少笔订单里」，**不能跨商品相加当总订单数**，也不能和门店销售表的订单数直接对比。
{{< /notice >}}

{{< notice info "产品销售汇总天然小于门店销售汇总" >}}
`food_di` 只统计商品行，不含快递等非商品营业额和补录营业额，所以同日同店的产品流水合计会小于门店销售表。对账时不要拿两张表的总流水直接比。详见 [产品销售（来源渠道）]({{< ref "/schema/ads/ads_dbs_trade_food_di" >}})。
{{< /notice >}}
