# 周边数据分析

零食部门周边产品销售与报货数据分析：CSV 源数据经 Python 写入 MySQL，再由 Excel Power Query 经 ODBC 拉取生成报表。

- **项目仓库**：<https://e.coding.net/fuwenyue/tianlala/snacks_sales.git>
- **数据依赖**：
  - 中台导出三份 CSV：周边产品销售 / 周边产品报货 / 门店流水（查询 SQL 见下文）
  - 门店主数据 `Tianlala.shop_current`（[门店信息管理]({{< ref "/projects/daily/门店信息管理" >}}) 每日重建）

## 数据流程

```text
周边产品销售/报货/门店流水 CSV → Python 汇总合并 → MySQL
→ Excel Power Query（ODBC）关联门店主数据 → 报表
```

## 数据表

**`zhoubian_data` 库**（Python 写入，详表 replace 全量重建）：

| 表名 | 内容 |
|---|---|
| 周边销售详表 | 各门店各产品销售明细 |
| 周边报货详表 | 各门店报货明细 |
| 门店销售 | 门店流水/实收/订单数/营业天数 |
| 周边产品销量排名 | 按产品+月份汇总 |
| 汇总表 | 三表按 门店+月份 合并 |

## 运行方式

1. 三个源 CSV 放入 `data/`，执行 `python main.py`
2. 打开当月 `周边数据_YYYYMM.xlsx`
3. 首次使用需在 Excel 数据源设置中配置 ODBC 凭据（`MySQL ODBC Unicode Driver`，root/123456）
4. 修改 .m 文件中 `shared TargetMonth = YYYYMM;` 后「全部刷新」

## 源数据查询

{{< notice warning "通用注意事项" >}}
1. 时间范围 `2025-01-01` ~ `2025-12-31` 是示例，实际查询时改为目标年份。
2. DWD/ADS 表**必须加 `pt` 或 `business_date` 分区裁剪条件**，否则全表扫。
3. 日期类型是 `varchar`（不是 `DATE`），字符串比较依赖存储格式，建议用 `CAST(STR_TO_DATE(...))` 转一下。
{{< /notice >}}

### 周边产品销售

**来源**：`ads_dbs_trade_food_di`（[文档]({{< ref "/data-dictionary/ads/ads_dbs_trade_food_di" >}})）
**过滤条件**：`food_category_name IN ('周边产品', '周边')`
**营业天数**：只有当日销量 > 0 才计入（产品售卖天数）

```sql
-- 周边产品按门店 × 产品 × 月份汇总
SELECT
    stat_shop_id                                                          AS 门店编号,
    item_name                                                             AS 周边产品名称,
    LEFT(business_date, 6)                                                AS 月份,
    SUM(dp_item_count)                                                    AS 周边产品销量,
    SUM(dp_total_amount)                                                  AS 周边产品流水,
    -- 严格判断：只有当日销量 > 0 才计入售卖天数，避免零销量日污染
    COUNT(DISTINCT CASE WHEN dp_item_count > 0 THEN business_date END)   AS 产品售卖天数
FROM tll_bi_dw.ads_dbs_trade_food_di
WHERE pt >= '20250101' AND pt < '20260101'   -- ✅ 分区裁剪，否则全表扫
  AND food_category_name IN ('周边产品', '周边')
GROUP BY stat_shop_id, item_name, LEFT(business_date, 6)
HAVING SUM(dp_item_count) > 0                -- 排除全年零销量的产品（减少 CSV 体积）
ORDER BY 门店编号, 周边产品名称, 月份;
```

### 周边产品报货

**来源**：`dwd_rps_tll_order_di`（头表，[文档]({{< ref "/data-dictionary/dwd/dwd_rps_tll_order_di" >}})）+ `dwd_rps_tll_order_details_di`（详表，[文档]({{< ref "/data-dictionary/dwd/dwd_rps_tll_order_details_di" >}})）
**关联键**：头表 `id` = 详表 `order_id`
**周边筛选**：详表 `sku_code LIKE '108%'`
**有效订单**：`order_status >= 3 AND order_status != 5`（排除已取消和驳回）
**去重**：同一订单号只取最新一条（防御头表可能存在的重复）

```sql
WITH
-- ① 订单头：先分区裁剪，再取字段
--    order_status 枚举：1待支付 2支付超时取消 3待确认 4-6部分取消 7备货 8配送 9已完成
--    过滤 >=3 排除待支付，!=5 排除驳回
report_order AS (
    SELECT
        id          AS 订单ID,
        order_num   AS 订单编号,
        order_status AS 订单状态,
        order_time  AS 订单时间,
        order_type  AS 订单类型,
        order_notes AS 订单备注,
        store_code  AS 门店编号
    FROM tll_bi_dw.dwd_rps_tll_order_di
    WHERE pt >= '20250101' AND pt < '20260101'   -- ✅ 分区裁剪
),

-- ② 头表去重：防御同一订单号在不同批次有重复记录
--    如果确认源表一单一头可删掉这层，但保留成本低
unique_orders AS (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY 订单ID ORDER BY 订单时间 DESC) AS rn
    FROM report_order
),

-- ③ 订单详表：同样先分区裁剪
report_order_details AS (
    SELECT
        id                AS 详单ID,
        order_id          AS 订单ID,       -- 关联头表
        product_info      AS 存货名称,
        product_specification AS 存货规格,
        product_id        AS 产品ID,
        sku_code          AS 存货编码,
        quantity          AS 下单数量,
        cancel_quantity   AS 取消数量,     -- 🔸 扣减已取消的报货量
        actual_amount     AS 实际金额
    FROM tll_bi_dw.dwd_rps_tll_order_details_di
    WHERE pt >= '20250101' AND pt < '20260101'   -- ✅ 分区裁剪
),

-- ④ 关联 + 过滤
summary_table AS (
    SELECT
        uo.门店编号,
        rod.存货名称,
        rod.实际金额,
        rod.下单数量 - IFNULL(rod.取消数量, 0)   AS 有效报货数量,
        uo.订单时间
    FROM unique_orders uo
    JOIN report_order_details rod ON uo.订单ID = rod.订单ID
    WHERE rod.存货编码 LIKE '108%'                                      -- 周边产品 sku 前缀
      AND uo.订单状态 >= 3 AND uo.订单状态 != 5                         -- 有效订单
      AND uo.rn = 1                                                     -- 去重：只取最新一条
      AND CAST(STR_TO_DATE(uo.订单时间, '%Y-%m-%d') AS DATE) >= '2025-01-01'
      AND CAST(STR_TO_DATE(uo.订单时间, '%Y-%m-%d') AS DATE) <  '2026-01-01'
)

-- ⑤ 最终汇总
SELECT
    门店编号,
    存货名称,
    DATE_FORMAT(订单时间, '%Y%m')   AS 月份,
    SUM(有效报货数量)               AS 周边报货数量,
    SUM(实际金额)                   AS 周边报货金额
FROM summary_table
GROUP BY 门店编号, 存货名称, DATE_FORMAT(订单时间, '%Y%m')
ORDER BY 门店编号, 存货名称, 月份;
```

### 门店销售

**来源**：`ads_dbs_trade_shop_pay_channel_di`（[文档]({{< ref "/data-dictionary/ads/ads_dbs_trade_shop_pay_channel_di" >}})）
**门店筛选**：`shop_id LIKE 'TLL%' OR 'ZYD%'`（甜啦啦主品牌 + 自有品牌）
**营业天数**：只有当日流水 > 0 才计入

```sql
SELECT
    shop_id                                                          AS 门店编号,
    LEFT(pt, 6)                                                      AS 月份,
    SUM(amount)                                                      AS 门店流水,
    SUM(income)                                                      AS 门店实收,
    SUM(order_cnt)                                                   AS 门店订单数,
    -- 严格判断：只有当日流水 > 0 才计入营业天数
    COUNT(DISTINCT CASE WHEN amount > 0 THEN pt END)                 AS 门店营业天数
FROM tll_bi_dw.ads_dbs_trade_shop_pay_channel_di
WHERE pt >= '20250101' AND pt < '20260101'   -- ✅ 分区裁剪
  AND (shop_id LIKE 'TLL%' OR shop_id LIKE 'ZYD%')
GROUP BY shop_id, LEFT(pt, 6)
ORDER BY 门店编号, 月份;
```

## 三份 CSV 处理流程

1. 三份查询结果保存为：`周边产品销售查询.csv` / `周边产品报货查询.csv` / `门店流水查询.csv`
2. 放入项目仓库 `data/` 目录
3. 执行 `python main.py` 写入 `zhoubian_data` 库
4. 打开当月 `周边数据_YYYYMM.xlsx`，修改 `.m` 文件中 `shared TargetMonth = YYYYMM;` 后「全部刷新」
