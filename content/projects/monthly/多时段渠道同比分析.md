# 多时段渠道同比分析

从 `ads_dbs_trade_shop_pay_channel_di` 读取门店渠道销售数据，按三级渠道体系清洗聚合，生成多时段同比分析报表并写入 MySQL。

- **项目仓库**：<https://e.coding.net/fuwenyue/tianlala/multi_period_channel_summary.git>
- **数据依赖**：
  - 门店销售备份 `Tianlala.ads_dbs_trade_shop_pay_channel_di`，由 [门店销售数据同步]({{< ref "/projects/manage/门店销售数据同步" >}}) 维护
  - 门店管理表 `Tianlala.shop_current`，由 [门店信息管理]({{< ref "/projects/daily/门店信息管理" >}}) 每日重建
- **下游使用**：[月度数据概览]({{< ref "/projects/monthly/月度数据概览" >}}) 消费本项目的「全量数据 / 期数」表

## 输出表（库 `multi_period_channel_summary`，每次 DROP 重建）

| 表名 | 内容 |
|---|---|
| 全量数据 | 全量门店同比（各渠道流水/实收/订单数/营业天数/动销门店 + 汇总同比） |
| 存量数据 | 仅多年各月均有流水的存量门店 |
| 期数 | 查询时段对照表 |

## 配置

`config.yaml` 中维护源库/输出库连接与时段列表：

```yaml
periods:
  list: 20260101~20260131, 20270101~20270131   # 第一个=本期，第二个=同期，可追加
```

## 运行方式

```bash
pip install pandas pymysql pyyaml
python main.py
```

## 渠道维护

三级渠道（大渠道 / 中渠道 / 原始渠道）统一定义在 `cleaning_module.py` 的 `CHANNEL_TREE`，与站点 [渠道分组]({{< ref "/reference/渠道分组" >}}) 口径一致。新增原始渠道只需在树中加一条，大渠道分类与列排序自动推导。

运行时会做**渠道覆盖检测**：数据库出现未被 `CHANNEL_TREE` 覆盖的 `payment_channels` 值会立即告警，需先补渠道映射再出报表。

源表字段参见数据字典 [ads_dbs_trade_shop_pay_channel_di]({{< ref "/data-dictionary/ads/ads_dbs_trade_shop_pay_channel_di" >}})。
