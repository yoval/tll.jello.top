    门店报货金额#

    按指定月份统计各门店报货金额，数据来自门店报货订单头 + 详表合并日表。

    • 数据表：门店报货订单（合并版）（tll_bi_dw.dwd_rps_tll_order_data_merge_di）
    • 粒度：门店 × 月份
    • 金额口径：SUM(actual_num * discount_unit_price)。actual_num 已扣 SKU 取消量，头表/详表的 actual_amount 在下单后有部分取消时不会扣减，不能直接汇总
    • 有效订单：order_status >= 3 AND order_status != 5（排除待支付、驳回取消）
    • 输出列：门店编号、订单数、有效数量、报货金额

    SQL#

    推荐写法：分区条件直接写字面量，最稳，不依赖会话变量。

    SELECT
    store_code                                       AS 门店编号,
    COUNT(DISTINCT id)                               AS 订单数,
    SUM(actual_num)                                  AS 有效数量,
    ROUND(SUM(actual_num * discount_unit_price), 2)  AS 报货金额
FROM tll_bi_dw.dwd_rps_tll_order_data_merge_di
WHERE pt >= '20260901' AND pt <= '20260930'   -- 换月份只改这两处
  AND order_status >= 3 AND order_status != 5
GROUP BY store_code
ORDER BY 报货金额 DESC;

    如果想只改一处月份，可以用会话变量版本。但本环境实测不生效：SET @month = '2026-09' 执行后 @month 为 NULL，pt >= NULL 会让结果全空。日常直接用上面的字面量版。

    SET @month = '2026-09';   -- 只改这里

SELECT
    store_code                                       AS 门店编号,
    COUNT(DISTINCT id)                               AS 订单数,
    SUM(actual_num)                                  AS 有效数量,
    ROUND(SUM(actual_num * discount_unit_price), 2)  AS 报货金额
FROM tll_bi_dw.dwd_rps_tll_order_data_merge_di
WHERE pt >= CONCAT(REPLACE(@month, '-', ''), '01')   -- 20260901
  AND pt <= CONCAT(REPLACE(@month, '-', ''), '31')   -- 20260931，2 月没有 31 号分区，安全
  AND order_status >= 3 AND order_status != 5
GROUP BY store_code
ORDER BY 报货金额 DESC;
    订单数要 COUNT(DISTINCT id)

    本表每行是 订单 × SKU，一个订单会占多行（实测 2025-01 平均约 17.6 行/订单）。直接 COUNT(*) 是 SKU 行数，COUNT(DISTINCT id) 才是订单数。

    空结果排查

    pt 是 varchar(8) 的 20260901 这种字符串，分区条件直接写字面量最稳。实测踩过的坑：

    1. DATE_FORMAT(CAST(... AS DATE), '%Y%m%d') 在这个 Doris 环境里返回值不符合预期，pt >= 结果 整体不成立，结果为空
    2. 会话变量 @month 在本环境不生效，值为 NULL，pt >= NULL 同样让结果全空——已验证字面量版正常、变量版为空

    如果字面量版仍为空，只剩两种可能，用下面这句定位：

    SELECT
    COUNT(*)                                           AS 本月全部行,
    SUM(CASE WHEN order_status >= 3 AND order_status != 5 THEN 1 ELSE 0 END) AS 有效状态行,
    MIN(order_status) AS 最小状态,
    MAX(order_status) AS 最大状态,
    MIN(pt)           AS 最小分区,
    MAX(pt)           AS 最大分区
FROM tll_bi_dw.dwd_rps_tll_order_data_merge_di
WHERE pt >= '20260901' AND pt <= '20260930';
    • 本月全部行 = 0 → 该月还没分区，或 pt 实际格式与 20260901 不一致（看 最小/最大分区）
    • 本月全部行 > 0 但 有效状态行 = 0 → order_status 全是 1/2/5，去掉状态过滤先看原值分布

    参数调整#

    • 排除直营店领料：加 AND order_type <> 3（order_type：1-普通 2-待客下单 3-直营店领料）
    • 只看周边产品：加 AND sku_code LIKE '108%'
    • 只看某门店：加 AND store_code = 'TLL00001'
    • 按商品拆开：GROUP BY 改成 store_code, product_info, sku_code，SELECT 加 product_info、sku_code
    • 只要全月合计：去掉 store_code 分组（或加一层外层聚合 SUM(报货金额)）

    注意事项#

    1. 金额用 merge 推导值，不要用 order_amount（下单原始金额，不扣取消）或详表 actual_amount。有 SKU 取消的订单两者都会偏高，实测平均差额约 170 元。
    2. pt 是订单日期分区，月初月末都闭合，>= 20260901 AND <= 20260930 即整月。
    3. 取消/部分取消订单：order_status 为 6、13 的是「部分取消」，仍属有效订单，金额按 actual_num 自动只算未取消部分。
    4. 门店编码：用 store_code（下单门店）。real_store_code 是真实门店 code，两者通常一致，若做门店主数据关联对不上时可回看该字段。
    5. 当年/当月分区会被中台回刷，跨月复制跑历史月份时数字可能轻微变动。
