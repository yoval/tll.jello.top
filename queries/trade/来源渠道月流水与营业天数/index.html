    来源渠道月流水与营业天数#

    按门店 × 月份 × 来源渠道统计流水、实收、订单数，并计算门店 / 渠道营业天数。

    • 数据表：ads_dbs_trade_shop_di
    • 粒度：门店 × 月份 × 来源渠道
    • 指标：流水 total_amount、实收 pay_amount、订单数 order_count

    结果列：门店编号，月份，门店营业天数，渠道，渠道营业天数，流水，实收，订单数

    SQL#

    WITH daily AS (
    -- 门店 × 日期 × 渠道组 日明细（先把明细渠道归并成 4 组）
    SELECT 
        shop_id,
        business_date,
        DATE_FORMAT(business_date, '%Y-%m') AS ym,
        CASE
            WHEN channel_name IN ('美团外卖', '京东外卖', '自营外卖', '淘宝闪购') THEN '外卖'
            WHEN channel_name IN ('微信小程序', '支付宝小程序', '小程序')     THEN '小程序'
            WHEN channel_name = 'pos收银'                                      THEN 'POS'
            WHEN channel_name IN ('美团/大众点评团购', '美团在线点', '抖音团购',
                                  '抖音小程序（核销工具）', '快手团购', '高德团购') THEN '团购'
        END AS channel_group,
        SUM(total_amount) AS total_amount,
        SUM(pay_amount)   AS pay_amount,
        SUM(order_count)  AS order_count
    FROM tll_bi_dw.ads_dbs_trade_shop_di
    WHERE business_date LIKE '2026%'
    GROUP BY shop_id, business_date, channel_group
),
store_day AS (
    -- 门店营业天数：先按 门店×日 跨渠道组合计，再判断 > 0
    SELECT shop_id, ym, COUNT(*) AS store_days
    FROM (
        SELECT shop_id, business_date, ym
        FROM daily
        GROUP BY shop_id, business_date, ym
        HAVING SUM(total_amount) > 0
    ) t
    GROUP BY shop_id, ym
),
channel_stat AS (
    SELECT 
        shop_id,
        ym,
        channel_group,
        COUNT(CASE WHEN total_amount > 0 THEN 1 END) AS channel_days,
        ROUND(SUM(total_amount), 2)                  AS total_amt,
        ROUND(SUM(pay_amount), 2)                    AS pay_amt,
        SUM(order_count)                             AS order_cnt
    FROM daily
    GROUP BY shop_id, ym, channel_group
)
SELECT 
    c.shop_id        AS 门店编号,
    c.ym             AS 月份,
    s.store_days     AS 门店营业天数,
    c.channel_group  AS 渠道,
    c.channel_days   AS 渠道营业天数,
    c.total_amt      AS 流水,
    c.pay_amt        AS 实收,
    c.order_cnt      AS 订单数
FROM channel_stat c
LEFT JOIN store_day s ON c.shop_id = s.shop_id AND c.ym = s.ym
ORDER BY c.shop_id, c.ym, c.channel_group;

    口径说明#

    • 渠道：查询返回的是 4 组汇总渠道（外卖 / 小程序 / POS / 团购），不是明细渠道。明细渠道归并规则见 门店销售（来源渠道） 的"渠道分组（4 组归并）"。
    • 渠道营业天数：当日该渠道组流水 > 0，记 1 天。
    • 门店营业天数：当日该店全渠道组合计流水 > 0，记 1 天。必须先按 门店×日 汇总再判断，避免渠道组间正负抵消导致误判。

    参数调整#

    • 换年份：修改 business_date LIKE '2026%' 中的年份
    • 只看部分门店：在 daily 的 WHERE 里加 AND shop_id LIKE 'TLL%'（加盟店）或指定门店
    • 换回明细渠道：把 channel_group 的 CASE 替换成直接 channel_name（GROUP BY 也同步改），但门店营业天数逻辑不变
    • 数据量大：SQL 只拉 daily 层明细，再用 pandas 聚合，逻辑等价

    注意事项#

    注意
    • 门店营业天数是门店×月粒度指标，同一门店的每个渠道行上数值相同。下游再汇总时不能 SUM(门店营业天数)，要按门店去重或取 MAX。
    • 门店整月所有渠道流水都 ≤ 0 时，store_day 无该门店记录，门店营业天数 为 NULL（LEFT JOIN 保留渠道行）。
    • 与支付渠道版口径不同，本查询结果不要和 ads_dbs_trade_shop_pay_channel_di 按渠道对比，只比总额。

    旧版表完整查询（2025 年以前）#

    2025 年以前的数据在旧版服务器上的同名表（表名也是 ads_dbs_trade_shop_di，只是部署在不同服务器），查询逻辑相同，字段和渠道口径已适配：

    WITH daily AS (
    -- 旧版表：门店 × 日期 × 渠道组 日明细（旧版渠道少，CASE 更简单）
    SELECT 
        stat_shop_id,
        business_date,
        business_date DIV 100 AS ym,          -- bigint 日期 → yyyyMM 整数
        CASE
            WHEN channel_name IN ('美团外卖', '饿了么外卖', '自营外卖') THEN '外卖'
            WHEN channel_name = 'pos'                                   THEN 'POS'
            WHEN channel_name = '小程序'                                THEN '小程序'
        END AS channel_group,
        SUM(total_amount) AS total_amount,
        SUM(pay_amount)   AS pay_amount,
        SUM(order_count)  AS order_count
    FROM tll_bi_dw.ads_dbs_trade_shop_di        -- 在旧版服务器上执行（同名表，旧版字段）
    WHERE business_date >= 20240101 AND business_date < 20250101
    GROUP BY stat_shop_id, business_date, channel_group
),
store_day AS (
    SELECT stat_shop_id, ym, COUNT(*) AS store_days
    FROM (
        SELECT stat_shop_id, business_date, ym
        FROM daily
        GROUP BY stat_shop_id, business_date, ym
        HAVING SUM(total_amount) > 0
    ) t
    GROUP BY stat_shop_id, ym
),
channel_stat AS (
    SELECT 
        stat_shop_id,
        ym,
        channel_group,
        COUNT(CASE WHEN total_amount > 0 THEN 1 END) AS channel_days,
        ROUND(SUM(total_amount), 2)                  AS total_amt,
        ROUND(SUM(pay_amount), 2)                    AS pay_amt,
        SUM(order_count)                             AS order_cnt
    FROM daily
    GROUP BY stat_shop_id, ym, channel_group
)
SELECT 
    c.stat_shop_id   AS 门店编号,
    c.ym             AS 月份,
    s.store_days     AS 门店营业天数,
    c.channel_group  AS 渠道,
    c.channel_days   AS 渠道营业天数,
    c.total_amt      AS 流水,
    c.pay_amt        AS 实收,
    c.order_cnt      AS 订单数
FROM channel_stat c
LEFT JOIN store_day s ON c.stat_shop_id = s.stat_shop_id AND c.ym = s.ym
ORDER BY c.stat_shop_id, c.ym, c.channel_group;

    与新版查询的差异点：

    差异 新版 旧版
    日期字段 business_date varchar，LIKE '2026%' business_date bigint，数值范围过滤
    月份取值 DATE_FORMAT(..., '%Y-%m') → 2026-01 business_date DIV 100 → 202401 整数
    门店字段 shop_id stat_shop_id
    渠道值 4 组汇总：外卖 / 小程序 / POS / 团购（14 条明细归并） 3 组汇总：外卖 / POS / 小程序（5 条明细归并）
    跨期拼接注意
    • 新旧两版表名完全相同，区别在服务器/连接——执行前先确认连的是哪台，连错服务器会因字段不存在直接报错。
    • 旧版"饿了么外卖"就是新版"淘宝闪购"（2025 年更名），两版都归到外卖组，口径一致，可以直接 UNION。
    • 新旧结果 UNION 前先统一月份格式（2026-01 vs 202401）和门店字段名（shop_id vs stat_shop_id）。
